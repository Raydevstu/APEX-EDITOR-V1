// TL;DR

ApexPad is a mature editor interface with an excellent whisper-strategy color system in OKLCH (violet-indigo accent, brand-tinted neutrals, authored dark mode) and a well-tokenized motion system. The design earns a 38/50. Three clusters of weakness: a crowded header with seven equally-weighted icon buttons, a flat type hierarchy where the brand text is only 13px, and interaction gaps including a tiny tab-close hit target, a tool list that bypasses the shared IconButton component, and a "diff viewer" that doesn't actually diff.

// WHAT'S WORKING

Color system

Whisper OKLCH strategy with violet-indigo accent (hue 262), brand-tinted neutrals (chroma < 0.02), and semantic state colors. Dark mode uses lightness steps for depth; light mode uses layered shadows.

Dark mode depth

Surfaces progress from oklch(0.135) to oklch(0.208) — authored depth, not inverted light-on-dark.

Motion system

Tokenized durations (150ms baseline, 250ms modal, 300ms drawer), expo-out easing, transform+opacity only, reduced-motion fallback to 150ms fades.

Dialog shell

Single reusable overlay component with backdrop blur, panel animation, Escape close, focus trap, and focus return. Used by all five modals.

Responsive tabs

Tab bar scrolls horizontally on mobile (390px) without overflow. Layout adapts cleanly across viewport sizes.

Editor theming

CodeMirror dark + light themes token-matched to design system. Syntax colors calibrated to canvas surfaces.

// PRIORITY ISSUES
P0

Header action hierarchy — seven equally-weighted buttons

Evidence: Header.tsx renders History, Tools, Share, Diff, Command Palette, Zen mode, and Theme toggle as IconButtons with identical visual weight. No grouping separates frequent actions from rare ones. Vision analysis confirms "7 icons tightly packed."

FIX: \design relayout — cluster actions (e.g. content actions vs. view controls) or move zen/theme behind a single overflow menu.
P1

Diff viewer is not a real diff

Evidence: DiffViewer.tsx (line 9–12) splits both snapshot and current content into lines and renders them in parallel. No diff algorithm runs — matching lines aren't aligned, and different line counts cause every subsequent line to shift and show as "changed." Dialog title says "Latest snapshot diff" (line 19).

FIX: \design redesign — implement a proper diff algorithm, or rename to "Snapshot comparison" to match the actual behavior.
P1

Tab close button is a touch-target risk

Evidence: TabBar.tsx (line 24) close button is p-1 with a 13px X icon — no enlarged hit area. IconButton has a ::before pseudo-element expanding to 44px+, but the tab close button doesn't use that pattern.

FIX: \design interaction — apply same hit-area enlargement as IconButton, or use IconButton for tab close.
P2

ToolDrawer bypasses shared IconButton

Evidence: ToolDrawer.tsx (lines 25–32) renders tool list items as plain <button> elements with manual classes, not the shared IconButton component. They lack the ::before hit-area expansion and touch-manipulation class.

FIX: \design interaction — use shared IconButton or apply the same hit-area treatment for consistency.
P2

⌘K commands button is disconnected

Evidence: App.tsx line 56 — fixed bottom-right z-10, no custom focus ring, no active state. Duplicates the command palette button already in the header (Terminal icon). On small screens it overlaps content.

FIX: \design relayout — remove (header already has command palette) or integrate into header.
P2

Flat type hierarchy

Evidence: Brand "ApexPad" at 13px (Header.tsx line 38), tab labels at 12px, footer stats at 11px. The lg (16px) and xl (18px) tokens in tailwind.config.js are unused. No clear primary/secondary/tertiary text distinction.

FIX: \design typeset — enlarge brand text, use defined type scale for hierarchy.
